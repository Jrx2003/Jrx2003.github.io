## 一、虚拟化概述

虚拟化是通过软件模拟硬件功能，将物理资源抽象成多个虚拟资源的技术。

### 虚拟化层次

```
┌─────────────────────────────────────────────────────────────┐
│                   应用层 (Applications)                   │
├─────────────────────────────────────────────────────────────┤
│              操作系统层 (Guest OS)                        │
├─────────────────────────────────────────────────────────────┤
│         虚拟化层 (Hypervisor / Container Runtime)       │
├─────────────────────────────────────────────────────────────┤
│             物理硬件层 (Physical Hardware)                │
│   CPU | 内存 | 磁盘 | 网卡 | GPU | ...                  │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、Type 1 vs Type 2 虚拟化

### Type 1 - 裸金属虚拟化 (Bare Metal)

Hypervisor 直接运行在硬件上，无需宿主机 OS。

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   Guest OS   │  │   Guest OS   │  │   Guest OS   │
│  (虚拟机 1)  │  │  (虚拟机 2)  │  │  (虚拟机 3)  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │                │                │
       └────────────────┼────────────────┘
                        │
               ┌───────────▼───────────┐
               │    Hypervisor (KVM)  │
               └───────────┬───────────┘
                           │
                   ┌───────▼────────┐
                   │  Physical HW  │
                   └───────────────┘
```

| 特性 | 说明 |
|------|------|
| 性能 | 接近裸金属，损耗小 |
| 安全 | 隔离性强 |
| 代表 | KVM、Xen、VMware ESXi |

### Type 2 - 寄居虚拟化 (Hosted)

Hypervisor 运行在宿主机 OS 上。

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   Guest OS   │  │   Guest OS   │  │   Guest OS   │
│  (虚拟机 1)  │  │  (虚拟机 2)  │  │  (虚拟机 3)  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │                │                │
       └────────────────┼────────────────┘
                        │
               ┌──────────▼───────────┐
               │  Hypervisor (VBox)  │
               └──────────┬───────────┘
                        │
               ┌────────▼─────────┐
               │   Host OS       │
               └────────┬─────────┘
                        │
                   ┌────▼────┐
                   │ Physical│
                   │   HW   │
                   └─────────┘
```

| 特性 | 说明 |
|------|------|
| 性能 | 有额外一层转换，损耗大 |
| 便捷 | 安装简单，适合个人使用 |
| 代表 | VirtualBox、VMware Workstation |

## 三、KVM 虚拟化

### KVM 原理

KVM (Kernel-based Virtual Machine) 将 Linux 内核变成 Hypervisor。

| 组件 | 说明 |
|------|------|
| **KVM 模块** | 在内核空间提供虚拟化支持 |
| **QEMU** | 用户空间，模拟硬件设备 |
| **libvirt** | 虚拟化管理接口 |

### KVM 网络模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **Bridge** | 虚拟机直接桥接到物理网络 | 需要独立 IP 的虚拟机 |
| **NAT** | 虚拟机通过宿主机访问外网 | 开发测试环境 |
| **Host-only** | 仅宿主机和虚拟机互通 | 内网隔离 |

## 四、容器技术

### 容器 vs 虚拟机

| 维度 | 虚拟机 | 容器 |
|------|---------|------|
| 架构 | 完整的 OS | 共享宿主 OS 内核 |
| 隔离 | 硬件级隔离 | 进程级隔离 |
| 启动时间 | 分钟级 | 秒级 |
| 镜像大小 | GB 级 | MB 级 |
| 性能损耗 | 5-15% | < 5% |

### 容器技术栈

```
应用 (App)
    │
├──────────────┬──────────────┬──────────────┐
│              │              │              │
 Docker      Podman       Containerd    rkt
│              │              │              │
└──────┬───────┘              │              │
       │                      │              │
┌──────▼──────────────────────▼──────────────▼──────────────┐
│                  Container Runtime                       │
├──────────────────────────────────────────────────────────────┤
│           Linux Namespaces + Cgroups                    │
└──────────────────────────────────────────────────────────────┘
│
└───────────┬──────────┐
            │          │
         runc      kata (安全容器)
```

## 五、容器核心技术

### 1. Namespace - 资源隔离

| Namespace | 隔离内容 |
|-----------|----------|
| **PID** | 进程 ID |
| **NET** | 网络栈 |
| **IPC** | 进程间通信 |
| **MNT** | 挂载点 |
| **UTS** | 主机名 |
| **USER** | 用户组 |

### 2. Cgroups - 资源限制

| 资源 | 控制参数 |
|------|----------|
| CPU | cpu.shares, cpu.cfs_quota_us |
| 内存 | memory.limit_in_bytes |
| 磁盘 I/O | blkio.throttle.read_bps |

## 七、安全容器

### 传统容器 vs 安全容器

| 特性 | 传统容器 | 安全容器 (Kata/ gVisor) |
|------|----------|------------------------|
| 共享内核 | 是 | 否 |
| 隔离级别 | 进程级 | 虚拟机级 |
| 性能损耗 | 低 | 中等 |
| 适用场景 | 通用 | 多租户、高安全要求 |

### Kata Containers

```
┌────────────────────────────────────────────┐
│          Pods (Kubernetes)               │
├────────────────────────────────────────────┤
│  ┌────────┐  ┌────────┐  ┌────────┐  │
│  │ Pod 1  │  │ Pod 2  │  │ Pod 3  │  │
│  │ Kata   │  │ Docker │  │ gVisor │  │
│  └───┬────┘  └───┬────┘  └───┬────┘  │
└───────┼──────────┼──────────┼─────────┘
        │          │          │
    ┌───▼───┐  ┌───▼───┐  ┌───▼───┐
    │ VM 1  │  │VM-like│  │ VMM   │
    └───────┘  └───────┘  └───────┘
        │          │          │
    ┌───▼──────────▼──────────▼────────┐
    │      Physical Hardware           │
    └──────────────────────────────────┘
```

## 八、面试要点

### 高频问题

1. **容器和虚拟机的根本区别？**
   - 虚拟机：硬件级虚拟化，独立 OS
   - 容器：操作系统级虚拟化，共享内核

2. **Docker 的 Namespace 和 Cgroups 作用？**
   - Namespace：隔离环境（进程、网络、文件系统）
   - Cgroups：限制资源（CPU、内存）

3. **Kata 相比 Docker 的优势？**
   - 独立内核，更强隔离
   - 适合多租户场景
   - 牺牲部分性能换取安全

4. **如何选择容器运行时？**
   - Docker：通用场景，追求性能
   - Kata：多租户、高安全要求
   - gVisor：中等隔离，性能损耗较小

## 八、面试要点

### 高频问题

1. **容器和虚拟机的根本区别？**
   - 虚拟机：硬件级虚拟化，独立 OS
   - 容器：操作系统级虚拟化，共享内核

2. **Docker 的 Namespace 和 Cgroups 作用？**
   - Namespace：隔离环境（进程、网络、文件系统）
   - Cgroups：限制资源（CPU、内存）

3. **Kata 相比 Docker 的优势？**
   - 独立内核，更强隔离
   - 适合多租户场景
   - 牺牲部分性能换取安全

4. **如何选择容器运行时？**
   - Docker：通用场景，追求性能
   - Kata：多租户、高安全要求
   - gVisor：中等隔离，性能损耗较小
