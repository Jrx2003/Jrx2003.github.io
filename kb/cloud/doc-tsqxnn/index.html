一、虚拟化概述

虚拟化是通过软件模拟硬件功能，将物理资源抽象成多个虚拟资源的技术。

虚拟化层次

┌─────────────────────────────────────────────────────────────┐
│                   应用层 (Applications)                   │
├─────────────────────────────────────────────────────────────┤
│              操作系统层 (Guest OS)                        │
├─────────────────────────────────────────────────────────────┤
│         虚拟化层 (Hypervisor / Container Runtime)       │
├─────────────────────────────────────────────────────────────┤
│             物理硬件层 (Physical Hardware)                │
│   CPU | 内存 | 磁盘 | 网卡 | GPU | ...                  │
└─────────────────────────────────────────────────────────────┘

二、Type 1 vs Type 2 虚拟化

Type 1 - 裸金属虚拟化 (Bare Metal)

Hypervisor 直接运行在硬件上，无需宿主机 OS。

┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   Guest OS   │  │   Guest OS   │  │   Guest OS   │
│  (虚拟机 1)  │  │  (虚拟机 2)  │  │  (虚拟机 3)  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │                │                │
       └────────────────┼────────────────┘
                        │
               ┌───────────▼───────────┐
               │    Hypervisor (KVM)  │
               └───────────┬───────────┘
                           │
                   ┌───────▼────────┐
                   │  Physical HW  │
                   └───────────────┘
特性说明
性能接近裸金属，损耗小
安全隔离性强
代表KVM、Xen、VMware ESXi

Type 2 - 寄居虚拟化 (Hosted)

Hypervisor 运行在宿主机 OS 上。

┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│   Guest OS   │  │   Guest OS   │  │   Guest OS   │
│  (虚拟机 1)  │  │  (虚拟机 2)  │  │  (虚拟机 3)  │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │                │                │
       └────────────────┼────────────────┘
                        │
               ┌──────────▼───────────┐
               │  Hypervisor (VBox)  │
               └──────────┬───────────┘
                        │
               ┌────────▼─────────┐
               │   Host OS       │
               └────────┬─────────┘
                        │
                   ┌────▼────┐
                   │ Physical│
                   │   HW   │
                   └─────────┘
特性说明
性能有额外一层转换，损耗大
便捷安装简单，适合个人使用
代表VirtualBox、VMware Workstation

三、KVM 虚拟化

KVM 原理

KVM (Kernel-based Virtual Machine) 将 Linux 内核变成 Hypervisor。

组件说明
KVM 模块在内核空间提供虚拟化支持
QEMU用户空间，模拟硬件设备
libvirt虚拟化管理接口

KVM 网络模式

模式说明适用场景
Bridge虚拟机直接桥接到物理网络需要独立 IP 的虚拟机
NAT虚拟机通过宿主机访问外网开发测试环境
Host-only仅宿主机和虚拟机互通内网隔离

八、面试要点

高频问题

  1. 容器和虚拟机的根本区别？

    • 虚拟机：硬件级虚拟化，独立 OS
    • 容器：操作系统级虚拟化，共享内核

  2. Docker 的 Namespace 和 Cgroups 作用？

    • Namespace：隔离环境（进程、网络、文件系统）
    • Cgroups：限制资源（CPU、内存）

  3. Kata 相比 Docker 的优势？

    • 独立内核，更强隔离
    • 适合多租户场景
    • 牺牲部分性能换取安全

  4. 如何选择容器运行时？

    • Docker：通用场景，追求性能
    • Kata：多租户、高安全要求
    • gVisor：中等隔离，性能损耗较小
